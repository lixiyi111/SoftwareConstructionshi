# StudyFlow —— TaskService 接口单元测试点清单

> 基于接口定义及 `docs/接口契约说明.md` 中的契约规范设计。

---

## 设计假设

1. **依赖隔离**：测试时通过构造函数注入 `InMemoryTaskRepository`，不涉及真实 IO。
2. **Task 实体**：构造函数签名已知（含 `userId`、`title`、`description`、`priority`、`status`、`createdAt`、`deadline` 等字段），默认状态为 `PENDING`。
3. **状态枚举值**：`PENDING` / `IN_PROGRESS` / `COMPLETED`；优先级枚举值：`HIGH` / `MEDIUM` / `LOW`。
4. **仓储行为**：`save` 覆盖写，`findById` 返回 `undefined` 表示不存在，`findAll` 返回全部任务，`delete` 移除。
5. **taskId 生成**：UUID v4，不重复。
6. **userId 归属**：不同 userId 的任务互不干扰（多用户隔离）。
7. **标题校验规则**：空字符串或纯空格均判定为"空"。
8. **状态转换规则（INV-04）**：`PENDING ↔ IN_PROGRESS → COMPLETED ↔ PENDING`（即 `COMPLETED` 可重置为 `PENDING`，`PENDING` 不可直接跳 `COMPLETED`）。
9. **截止日期匹配规则**：`deadline <= 传入 date 当日 23:59:59` 算"到期"；未设置 deadline 的任务不参与匹配。

## 测试点清单

## createTask

### 正常路径

* **TP001**：传入合法的 `CreateTaskCommand`（含 title、priority、userId），应返回 `Task` 对象，且 `status` 为 `PENDING`、`taskId` 不为空
* **TP002**：传入包含全部可选字段（description、dueDate）的命令，应正确设置 description 和 deadline 属性

### 异常路径

* **TP003**：title 为空字符串时，应抛出异常，提示"任务标题不能为空"
* **TP004**：priority 传入非法值（如 `"URGENT"`）时，应抛出异常，提示包含"无效优先级"

### 边界条件

* **TP005**：title 为纯空格字符串时，应抛出异常（同空标题处理）
* **TP006**：description 未传入（undefined）时，应默认为空字符串 `''`，不抛异常
* **TP007**：title 为长度 500 的字符串时，应正常创建且不截断

---

## completeTask

### 正常路径

* **TP008**：任务状态为 `IN_PROGRESS` 时调用 `completeTask`，应返回 `Task`，`status` 为 `COMPLETED`，`completedAt` 不为空

### 异常路径

* **TP009**：传入不存在的 `taskId` 时，应抛出异常，提示"任务不存在"

### 边界条件

* **TP010**：任务状态为 `COMPLETED` 时再次调用 `completeTask`，应抛出"不允许的状态转换"异常
* **TP011**：任务状态为 `PENDING` 时直接调用 `completeTask`（跳过 `IN_PROGRESS`），应抛出"不允许的状态转换"异常

---

## updateTaskStatus

### 正常路径

* **TP012**：`PENDING` → `IN_PROGRESS`，应返回更新后的 `Task`，`status` 为 `IN_PROGRESS`
* **TP013**：`COMPLETED` → `PENDING`（重置），应返回更新后的 `Task`，`status` 为 `PENDING`，`completedAt` 清空

### 异常路径

* **TP014**：传入非法 status 字符串（如 `"DONE"`）时，应抛出异常，提示包含"无效状态"
* **TP015**：`PENDING` → `COMPLETED`（非法跳转），应抛出"不允许的状态转换"异常
* **TP016**：`COMPLETED` → `IN_PROGRESS`（非法跳转），应抛出"不允许的状态转换"异常

### 边界条件

* **TP017**：`IN_PROGRESS` → `IN_PROGRESS`（相同状态），不涉及转换规则，观察是否被允许或拒绝（取决于实现）

---

## listTasksByPriority

### 正常路径

* **TP018**：某用户有 3 个任务（优先级分别为 LOW、HIGH、MEDIUM），返回的数组应按 HIGH → MEDIUM → LOW 排序
* **TP019**：同一优先级的任务应按入库顺序排列（先创建的先出现）

### 异常路径

* 无（userId 为空字符串时按正常流程返回空数组，不抛异常）

### 边界条件

* **TP020**：该用户没有任何任务时，应返回空数组 `[]`
* **TP021**：传入空字符串 `""` 作为 userId，应返回空数组（因为没有任务的 userId 是空串）
* **TP022**：用户只有同一个优先级的多个任务，应正常返回且排序稳定

---

## listDueTasks

### 正常路径

* **TP023**：传入日期 `2026-06-10`，任务中有 deadline 为 `2026-06-01`、`2026-06-10`、`2026-06-15` 各一条，应返回前两条（`<= 2026-06-10`）

### 异常路径

* 无（方法签名未定义 date 为 null/undefined 时的行为，假设由调用方保证传入有效 Date）

### 边界条件

* **TP024**：没有任何任务的 deadline 小于等于指定日期时，应返回空数组
* **TP025**：未设置 deadline 的任务不应出现在结果中
* **TP026**：deadline 精确等于指定日期当天的任务应被包含（当日 23:59:59 前均算到期）
* **TP027**：多条任务同一天到期，应全部返回

---

## getUserProgress

### 正常路径

* **TP028**：某用户有 5 个任务，其中 3 个 `COMPLETED`、1 个 `IN_PROGRESS`、1 个 `PENDING`，应返回 `{ total: 5, completed: 3 }`

### 异常路径

* 无（userId 不存在时返回 0/0，不抛异常）

### 边界条件

* **TP029**：该用户没有任何任务时，返回 `{ total: 0, completed: 0 }`
* **TP030**：该用户所有任务均为 `COMPLETED`，应返回 `{ total: N, completed: N }`
* **TP031**：该用户有任务但没有一个 `COMPLETED`，应返回 `{ total: N, completed: 0 }`
* **TP032**：其他用户的任务不计入当前用户的统计（多用户隔离）
