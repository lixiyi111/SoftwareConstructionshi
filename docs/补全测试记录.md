> 操作时间：2026-06-07

---

## 任务说明

在完成代码异味分析和重构方案设计后，、为重构实施做准备，按照"测试先行"原则，先补全缺失的领域层不变量测试。

这些测试只验证 Task 实体本身是否能保护自身完整性，不经过 Service 层。在补全时 Task 实体尚未添加任何校验逻辑，因此绝大多数测试预期失败——这精确标识了领域层当前缺失的校验行为，为后续四轮重构提供了可量化的进度指标。

---

## 使用的提示词

```
补全测试的任务如下：

根据 docs/不变量测试覆盖分析.md 中的建议新增测试列表，
补充 P0 和 P1 层级的缺少测试。

注意：
- P0 有 10 条测试（TC-01 ~ TC-10）
- P1 有 9 条测试（TC-11 ~ TC-19）
- 共 19 条测试

要求：
1. 对应格式：
   - TC-01 → TP033，以此类推到 TP051
   - 所有测试放在同一个文件：test/domain/TaskInvariant.test.ts
   - 每条测试使用 it('TPxxx 描述', ...) 格式

2. 命名规范：
   - TP033-035：INV-01 截止日期不能早于创建时间
   - TP036-038：INV-02 高优先级任务必须设置截止日期
   - TP039-041：INV-03 任务标题不能为空
   - TP042-047：INV-04 状态转换路径
   - TP048-051：INV-05 提醒时间不能晚于截止日期

3. 测试方式：
   - 直接 new Task(...) 或 task.updateStatus() / task.setReminderPolicy()
   - 不经过 Service
   - 使用 createBaseTask 辅助函数简化构造

4. 当前预期：
   - INV-01/02/03/05 的测试当前会失败（Task 实体无校验）
   - INV-04 的 TP045-047 当前会失败（updateStatus 无校验）
   - TP042-044 当前会通过（updateStatus 正常执行）
   - 在测试中标注当前预期会失败的原因

5. 禁止：
   - 不能修改任何生产代码（src/ 下的文件）
   - 不能修改已有测试
   - 不要实现业务逻辑

6. 输出：
   - 列出 TP033-TP051 共 19 条测试的位置和预期
   - 运行测试，确认预期失败的测试确实在失败
   - 报告当前测试结果
```

## 与已有测试的关系

| 维度 | 已有测试（TP001-TP032） | 新增测试（TP033-TP051） |
|------|----------------------|----------------------|
| 测试层次 | 应用层（通过 Service） | 领域层（直接构造实体） |
| 覆盖的不变量 | INV-03（间接）、INV-04（间接）、INV-06 | INV-01 ~ INV-05（直接） |
| 数据准备 | 需 mock repository | 无依赖，直接 new |
| 重构中的作用 | 验证外部行为不变 | 验证领域层自保护完整 |
