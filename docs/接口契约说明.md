# StudyFlow —— 接口契约说明

> 定义 `src/application/TaskService.ts` 中声明的 5 个核心接口，
> 以及实现类 `DefaultTaskService` 的行为规范。

---

## 总览

| 功能 | 接口方法 | 实现类方法 |
|------|---------|-----------|
| &创建任务 | `createTask` | `DefaultTaskService.createTask` |
| &更新任务状态 | `completeTask` / `updateTaskStatus` | `DefaultTaskService.completeTask` / `updateTaskStatus` |
| &按优先级排序 | `listTasksByPriority` | `DefaultTaskService.listTasksByPriority` |
| &查询到期任务 | `listDueTasks` | `DefaultTaskService.listDueTasks` |
| &按用户统计 | `getUserProgress` | `DefaultTaskService.getUserProgress` |

---

## 1. createTask

### 前置条件

- `title` 不能为空或纯空格
- `userId` 不能为空
- `priority` 必须为 `HIGH` / `MEDIUM` / `LOW` 之一

### 后置条件

- 返回新创建的 `Task` 对象
- 任务被保存到仓储中
- 默认状态为 `PENDING`
- 系统自动生成 UUID 作为 `taskId`

### 异常条件

| 条件 | 错误信息 |
|------|---------|
| title 为空或纯空格 | `任务标题不能为空` |
| priority 非法 | `无效优先级: xxx（可选: HIGH / MEDIUM / LOW）` |

### 边界情况

- `description` 为空 → 按空字符串 `''` 处理
- `dueDate` 为空 → 不设截止日期
- `title` 极长（如 500 字）→ 不做截断，保持原样

---

## 2. completeTask

### 前置条件

- `taskId` 存在

### 后置条件

- 任务状态变为 `COMPLETED`
- 自动记录 `completedAt` 时间
- 更新到仓储

### 异常条件

- `taskId` 不存在 → `任务不存在: {taskId}`

### 边界情况

- 已完成任务再次调用 → 遵从状态转换规则（`COMPLETED → COMPLETED` 不允许），抛出异常

---

## 3. updateTaskStatus

### 前置条件

- `taskId` 存在
- `status` 合法：`PENDING` / `IN_PROGRESS` / `COMPLETED`

### 后置条件

- 状态更新成功
- 更新到仓储

### 异常条件

| 条件 | 错误信息 |
|------|---------|
| status 非法 | `无效状态: xxx（可选: PENDING / IN_PROGRESS / COMPLETED）` |
| taskId 不存在 | `任务不存在: {taskId}` |
| 状态转换不允许 | `不允许的状态转换: {当前} → {目标}` |

### 边界情况

| 当前状态 | 允许的下一个状态 |
|---------|----------------|
| PENDING | IN_PROGRESS |
| IN_PROGRESS | COMPLETED |
| COMPLETED | PENDING（重置重新做） |

其他组合均拒绝。

---

## 4. listTasksByPriority

### 前置条件

- `userId` 存在（非空字符串即可）

### 后置条件

- 返回该用户的任务数组，按优先级权重排序（HIGH → MEDIUM → LOW）
- 同一优先级内保持入库顺序

### 边界情况

- 用户没有任务 → 返回空数组 `[]`
- 用户 ID 为空字符串 → 空数组

---

## 5. listDueTasks

### 前置条件

- `date` 为有效 `Date` 对象

### 后置条件

- 返回 `deadline <= date`（当天 23:59:59 前）的任务数组
- 不包含未设置 `deadline` 的任务

### 边界情况

- 没有到期任务 → 空数组
- 多个任务同一天到期 → 全部返回
- 任务是未来的截止日期 → 不包含

---

## 6. getUserProgress

### 前置条件

- `userId` 存在

### 后置条件

- 返回 `{ total: number, completed: number }`
- `total` = 该用户的总任务数
- `completed` = 该用户状态为 `COMPLETED` 的任务数

### 边界情况

- 用户没有任务 → `{ total: 0, completed: 0 }`

---

## 7. 依赖注入方式

```typescript
const repository = new InMemoryTaskRepository();
const taskService = new DefaultTaskService(repository);
const controller = new TaskController(taskService);
```

---

## 8. 完整使用示例

```typescript
import { InMemoryTaskRepository } from './infrastructure/TaskRepository';
import { DefaultTaskService } from './application/DefaultTaskService';
import { TaskController } from './interfaces/TaskController';

const ctrl = new TaskController(new DefaultTaskService(new InMemoryTaskRepository()));
const USER = 'student-001';

// &创建任务
ctrl.handleCreateTask({ userId: USER, title: '学 TypeScript', priority: 'HIGH' });

// &按优先级排序
ctrl.handleListByPriority(USER);

// &查询到期任务
ctrl.handleListDueTasks(new Date('2026-06-30'));

// &按用户统计
ctrl.handleShowProgress(USER);

// &更新任务状态
ctrl.handleCompleteTask('task-uuid-here');
ctrl.handleUpdateStatus('task-uuid-here', 'IN_PROGRESS');
```
