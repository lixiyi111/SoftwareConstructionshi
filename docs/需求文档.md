# StudyFlow 学习任务管理系统 —— 需求文档

## 1. 项目概述

StudyFlow 是一个面向学生个人使用的学习任务管理系统。学生可以通过它创建学习任务、管理优先级、设置提醒、更新任务进度，并查看自己的学习统计信息。

本项目为软件构造课程实验作品，设计原则是"够用就好"，不做大型商业系统的功能堆砌。

---

## 2. 用户角色

本系统只有一个用户角色：

### 2.1 学生（Student）

系统的唯一使用者。学生负责创建和管理自己的学习任务，查看学习数据。系统不涉及多用户、权限分级或团队协作。

---

## 3. 用户故事

| 编号 | 用户故事 |
|------|---------|
| US-01 | 作为一名学生，我希望能够创建学习任务，以便记录我需要完成的学习内容 |
| US-02 | 作为一名学生，我希望能够为任务设置优先级，以便合理安排学习顺序 |
| US-03 | 作为一名学生，我希望能够为任务设置截止日期和提醒，以免忘记学习计划 |
| US-04 | 作为一名学生，我希望能够将任务标记为不同状态（待开始、进行中、已完成），以便跟踪进度 |
| US-05 | 作为一名学生，我希望能够查看所有任务的列表，以便了解当前有哪些待办事项 |
| US-06 | 作为一名学生，我希望能够按状态或优先级筛选任务，以便快速找到特定类型的任务 |
| US-07 | 作为一名学生，我希望能够编辑和删除任务，以便纠正创建时的错误或移除不再需要的任务 |
| US-08 | 作为一名学生，我希望能够查看学习统计（如完成任务数、学习时长），以便了解自己的学习情况 |

## 4. 功能需求

### FR-01 创建学习任务

| 项目 | 内容 |
|------|------|
| 功能名称 | 创建学习任务 |
| 功能描述 | 学生可以创建一条新的学习任务，填写任务的基本信息 |
| 输入 | 任务标题（必填）、任务描述（选填）、优先级（必选，三级）、截止日期（选填）、预计时长（选填） |
| 输出/行为 | 系统保存任务并显示在任务列表中，状态默认为"待开始" |

### FR-02 查看任务列表

| 项目 | 内容 |
|------|------|
| 功能名称 | 查看任务列表 |
| 功能描述 | 学生可以查看所有学习任务的列表，按创建时间倒序排列 |
| 输入 | 无（默认进入页面即显示） |
| 输出/行为 | 系统以列表形式展示所有任务，每条任务显示：标题、优先级、状态、截止日期 |

### FR-03 设置任务优先级

| 项目 | 内容 |
|------|------|
| 功能名称 | 设置任务优先级 |
| 功能描述 | 学生在创建或编辑任务时，可以为任务设置优先级等级 |
| 输入 | 选择"高""中""低"三个等级之一 |
| 输出/行为 | 系统保存优先级设置，在列表中用不同颜色或标识区分：高优先级为红色，中优先级为黄色，低优先级为绿色 |

### FR-04 更新任务状态

| 项目 | 内容 |
|------|------|
| 功能名称 | 更新任务状态 |
| 功能描述 | 学生可以更改任务的状态，以反映任务的推进情况 |
| 输入 | 点击状态切换按钮，在"待开始→进行中→已完成"之间流转；已完成的任务可重置为"待开始" |
| 输出/行为 | 系统更新任务状态并在列表中即时反映；任务变为"已完成"时，记录完成时间 |

### FR-05 编辑任务

| 项目 | 内容 |
|------|------|
| 功能名称 | 编辑任务 |
| 功能描述 | 学生可以修改已创建任务的标题、描述、优先级、截止日期等信息 |
| 输入 | 在任务详情页修改任意可编辑字段并提交 |
| 输出/行为 | 系统保存修改后的内容并刷新展示，同时记录最后修改时间 |

### FR-06 删除任务

| 项目 | 内容 |
|------|------|
| 功能名称 | 删除任务 |
| 功能描述 | 学生可以删除不再需要的任务 |
| 输入 | 点击删除按钮，在弹出的确认对话框中点击"确认删除" |
| 输出/行为 | 系统将该任务从数据库中移除，任务列表不再显示该任务 |

### FR-07 筛选与搜索任务

| 项目 | 内容 |
|------|------|
| 功能名称 | 筛选与搜索任务 |
| 功能描述 | 学生可以按状态、优先级筛选任务，也可以按关键词搜索任务标题 |
| 输入 | 选择筛选条件（状态/优先级），或在搜索框中输入关键词 |
| 输出/行为 | 系统根据筛选/搜索条件展示匹配的任务列表；无匹配时显示"没有找到符合条件的任务"提示 |

### FR-08 查看学习统计

| 项目 | 内容 |
|------|------|
| 功能名称 | 查看学习统计 |
| 功能描述 | 学生可以查看自己的学习统计数据，了解整体学习情况 |
| 输入 | 点击进入统计页面 |
| 输出/行为 | 系统展示：总任务数、已完成任务数、完成率（百分比）、按优先级统计的任务分布、近7天完成的任务趋势 |

### FR-09 设置任务提醒

| 项目 | 内容 |
|------|------|
| 功能名称 | 设置任务提醒 |
| 功能描述 | 学生在创建或编辑任务时，可为任务设置提醒时间 |
| 输入 | 设置提醒日期和时间（需精确到分钟） |
| 输出/行为 | 系统在设定的提醒时间到来时，在页面内弹出提醒通知，显示"任务 [任务标题] 即将到期" |

### FR-10 搜索任务（补充）

| 项目 | 内容 |
|------|------|
| 功能名称 | 关键词搜索任务 |
| 功能描述 | 学生可以通过输入关键词搜索任务标题 |
| 输入 | 在搜索框中输入关键词（至少1个字符） |
| 输出/行为 | 系统实时显示标题包含该关键词的任务列表；清除搜索框内容后恢复完整列表 |

## 5. 非功能需求

### NFR-01 响应速度

系统界面操作响应时间不超过 1 秒。任务列表加载（100 条以内）时间不超过 2 秒。

### NFR-02 数据持久化

所有任务数据必须保存在本地存储（如 LocalStorage 或轻量级数据库）中，刷新页面或关闭浏览器后数据不丢失。

### NFR-03 易用性

系统界面应简洁清晰，所有核心功能（创建、编辑、删除、状态切换）应在 2 次点击内可完成。不需要用户查看使用说明即可上手操作。

### NFR-04 兼容性

系统应在 Chrome、Edge、Firefox 三款浏览器的最新版本上正常运行，界面布局不出现错乱。

### NFR-05 代码可维护性

项目代码应按照分层结构组织（如数据层、逻辑层、UI层分离），每个函数的长度原则上不超过 40 行。

## 6. 验收标准

### AC-01 创建任务验证

> 当学生在创建任务页面填写标题（如"完成软件构造实验报告"）、选择优先级为"高"、设置截止日期为 2026-06-10，然后点击"创建"按钮后，系统应在任务列表中显示该任务，标题显示为"完成软件构造实验报告"，优先级显示为红色"高"标签，状态显示为"待开始"。

### AC-02 状态流转验证

> 当学生在任务列表中点击某个"待开始"任务的"开始"按钮后，该任务的状态应变为"进行中"；再次点击"完成"按钮后，状态应变为"已完成"，并且系统应在任务详情中记录完成时间。

### AC-03 筛选功能验证

> 当学生在筛选区域选择状态为"已完成"后，任务列表应只显示状态为"已完成"的任务，不显示"待开始"或"进行中"的任务。当筛选条件切换为"全部"时，列表恢复显示所有任务。

### AC-04 删除确认验证

> 当学生在任务列表中点击某个任务的"删除"按钮时，系统应弹出确认对话框，显示"确定要删除此任务吗？"；学生点击"取消"时，任务不被删除；学生点击"确认删除"时，该任务从列表中消失且不可恢复。

### AC-05 数据持久化验证

> 学生在系统中创建至少 3 条任务并刷新浏览器页面后，所有任务应仍然存在于列表中，数据没有丢失。关闭浏览器后重新打开，数据仍然存在。

### AC-06 统计信息验证

> 当学生创建了 5 个任务，并将其中 3 个标记为"已完成"后，在统计页面中应显示：总任务数 = 5，已完成 = 3，完成率 = 60%。

### AC-07 搜索功能验证

> 当学生在搜索框中输入"实验"时，系统应只显示标题中包含"实验"二字的任务；如果没有任何任务标题包含该关键词，应显示"没有找到符合条件的任务"。
